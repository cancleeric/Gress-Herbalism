# 遊戲規則快速參考

> [產品規格與改編差異](PRODUCT_SPEC.md) · [完整QA案例](QA_ACCEPTANCE.md) · [既有規則](GAME_RULES.md)。本文件是玩家流程摘要，不代表功能已全部驗收。

## 核心規則要點

### ⚠️ 問牌規則（必須遵守）

1. **必須誠實給牌**：目標玩家不能拒絕給牌（除非真的沒有牌）
2. **有多少給多少**：如果要求的牌不足，給出所有符合條件的牌
3. **三種要牌方式**：
   - **方式1**：兩個顏色各一張 → 如果兩個顏色都有，各給一張（共2張）；如果只有一個顏色，只給該顏色一張（共1張）；如果都沒有，給「沒有」
   - **方式2**：其中一種顏色全部 → 由被問者選有牌的一色全部交出；兩色都沒有才「沒有」
   - **方式3**：給一張要全部 → 先給牌，然後要全部（沒有也要「沒有」，但已給出的牌不收回）

### ⚠️ 猜牌規則（必須遵守）

1. **查看答案**：猜牌時，猜牌者可以查看正確答案（蓋牌的實際顏色）
2. **猜對**：公布答案給所有玩家，該玩家獲勝
3. **猜錯**：本局失去主動行動資格、跳過本人回合；剩牌保密保留，仍可被問牌並須收交牌；不是離房
4. **只剩一個玩家**：必須執行猜牌動作（不能選擇問牌）
5. **最後一人猜錯**：遊戲結束，沒有獲勝者

## 遊戲流程圖

```
遊戲開始
  ↓
洗牌 → 抽2張蓋牌 → 發牌給玩家
  ↓
玩家輪流回合
  ↓
選擇動作：問牌 或 猜牌
  ↓
[問牌] → 選擇顏色 → 選擇目標 → 選擇方式 → 執行要牌 → 記錄結果
  ↓
[猜牌] → 選擇顏色並鎖定 → 其餘有資格者依序決策 → 驗證結果（不得先看答案）
  ↓
  猜對 → 公布答案 → 遊戲結束（有獲勝者）
  猜錯 → 蓋牌仍保密 → 停止主動行動（仍可被問牌）
         ↓
    只剩一個玩家？ → 是 → 必須猜牌
         ↓
    遊戲結束（有/無獲勝者）
```

## 關鍵數據結構

### 問牌動作結果
```javascript
{
  success: boolean,
  result: {
    cardsGiven: Card[],      // 發起玩家給出的牌（類型3）
    cardsReceived: Card[],    // 發起玩家收到的牌
    hasCards: boolean        // 目標玩家是否有牌（false = "沒有"）
  },
  message: string
}
```

### 猜牌動作結果
```javascript
{
  success: boolean,
  isCorrect: boolean,
  revealedCards: Card[] | null,  // 猜對時顯示的蓋牌
  message: string
}
```

### 遊戲結束條件
- `winner !== null` → 有獲勝者
- `winner === null && gamePhase === 'finished'` → 沒有獲勝者（最後一人猜錯）

## 常見問題

**Q: 問牌時可以拒絕給牌嗎？**  
A: 不可以。必須誠實給牌，有多少給多少。只有真的沒有牌時才返回「沒有」。

**Q: 猜牌時其他玩家能看到答案嗎？**  
A: 不可先看答案再選猜測。原版在答案承諾後由參與者私下查驗；現行數位版錯誤猜測不顯示答案，是待決策差異，猜對才公開。

**Q: 只剩一個玩家時可以做什麼？**  
A: 只能猜牌，不能問牌。系統會自動隱藏問牌按鈕。

**Q: 如果最後一個玩家猜錯會怎樣？**  
A: 遊戲結束，但沒有獲勝者。蓋牌保持隱藏。

**Q: 方式1要兩個顏色各一張，但目標只有一個顏色怎麼辦？**  
A: **只給該顏色一張**（不是給該顏色的全部）。方式1是「各一張」，所以如果只有一個顏色，就只給一張。有多少給多少，不能拒絕。

## 猜錯後還能做什麼？

不能再主動問牌、猜牌或跟猜，但仍留在座位，保留自己的私牌並履行他人的問牌。下一局恢復資格。僅剩最後一位有資格者時，該人必須立即猜牌；此時其他人仍在房內，不是只剩一人連線。
