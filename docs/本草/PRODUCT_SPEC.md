# 本草數位版遊戲企畫與驗收規格

版本：2026-11-01／11734；狀態：規格整理完成，產品尚未通過完整驗收。

## 1. 文件權責與範圍

- 本文件定義本草數位版的目標體驗與驗收要求；不以現有程式行為反推桌遊規則。
- [原規則／實作差異與淘汰規格](ELIMINATION_RULES_AND_QA.md)、[完整 QA 案例](QA_ACCEPTANCE.md) 必須一起閱讀。
- [既有完整規則](GAME_RULES.md) 是數位版歷史規格，不代表全部已實作或與原版一致。
- 修改玩法時必須同時更新規格、案例、玩家說明；工程測試通過不等於設計驗收通過。
- 本輪只有本機規格整理，不提交、不合併、不部署、不操作 DB。

## 2. 規則來源及差異決策

來源：EmperorS4 出版社 Herbalism 規則下載頁 https://en.emperors4.com/game/Herbalism 。英文 Curing 段落與規則書對照詳見補充文件。BGG 直接存取曾被403拒絕，未以未讀討論作依據。

| 項目 | 原規則／已核對依據 | 數位版現況 | 驗收處置 |
|---|---|---|---|
| 人數及牌組 | 3–4人，紅2黃3綠4藍5；2張藥方、12張私牌 | 支援單人加AI及多人 | 牌數守恆、不同模式均須驗證 |
| 猜錯後資格 | 跳過主動回合，仍可被行動選中；私牌保密 | 人類選人已有支援；AI目標篩選已修 | 不稱「離房」或「封存」 |
| 最後一人 | 必須立即執行猜藥 | UI限制及問牌處理補防線 | 不代選答案，不容許再問牌 |
| 同次猜藥 | 可另選答案、跟隨或不參與 | 目前主要為跟隨／不跟隨 | 功能缺口，未驗收；不得宣稱原版完整實現 |
| 看答案順序 | 先承諾答案，再由參與者私下查驗 | 錯誤猜測目前不發答案 | 改編差異待決策；嚴禁先看再選答案 |
| 同色組合 | 原規則以同色組合標記處理 | 目前選兩色可重複 | 語意及比對須獨立盤點；不能只靠既有測試自證 |
| 猜錯扣分 | 現有規則文件載猜者不扣、跟錯扣1 | 後端猜者0；單機猜者-1 | 已確認模式差異，列P1；不可把任一版本默認為核准玩法 |
| 整場門檻 | 原規則通常6分／可約定目標 | 程式及歷史文件採7分 | 數位改編現況，需明示；未擅改為6分 |
| 預測 | 原版有變體標記及相關規則 | 問牌後選色、結算加減分 | 僅作既有數位模式描述，完整原版一致性未確認 |
| 手牌歸零 | 本次未找到取消猜牌資格的依據 | 後端有部分歸零即 inactive 分支 | P1待核對與修正，不可寫成已通過 |

差異決策紀錄須包含依據、版本、負責人、是否改編及核准來源；未決項不得默默當正式規則發布。

## 3. 產品定位與手機優先

- 先確保320×568、390×844直向可玩，再處理橫向及桌機；實體裝置另列驗收，不以模擬尺寸取代。
- 主要操作觸控區至少44×44 CSS px；文字不得因美術背景降低可讀性。
- 遊戲場景以實體藥草牌、寶盒、桌面為視覺主角；面板只承載當下決策，不用大片空白報表。
- 平時寶盒靠桌邊，不遮住六張組合牌；點擊後中央放大。開局先中央大盒收兩張蓋牌、合蓋再縮回桌邊。
- 確認、取消、跟猜等主要操作固定於可見區；長內容在內部捲動；縮放、瀏海及底部安全區不能遮擋。
- 動畫以清楚可辨的發起者／收牌者落點為準，不以執行速度作成功標準；尊重減少動態效果設定。

## 4. 玩家能力與資訊界線

| 身分 | 可主動問牌／猜牌 | 可跟猜 | 可被問牌／收交牌 | 可見私牌 | 下局 |
|---|---|---|---|---|---|
| 有資格且當前回合 | 可以；僅剩一人時只能猜 | 跟猜階段依序處理 | 可以 | 僅自己 | 保留座位與分數 |
| 有資格且非回合 | 不可以 | 輪到決策時可以 | 可以 | 僅自己 | 同上 |
| 猜錯／跟錯 | 不可以 | 不可以 | 可以，仍須履行回應 | 僅自己，不公開 | 洗牌後恢復資格 |
| 斷線 | 不等於猜錯；恢復流程另行處理 | 不得代送本人決定 | 逾時／恢復策略待驗 | 以原身分重連才可見 | 不因猜錯邏輯移除座位 |
| 已離房 | 不可以 | 不可以 | 不應作目標 | 不再取得新私有事件 | 重新加入依房規 |

資料實作暫用 isActive 表示主動資格；它不能同時代表是否在線、是否有座位、是否可作問牌目標。現有斷線／歸零分支需獨立驗證，不以此表宣稱已全部分離。

## 5. 開局與狀態流程

1. 多人房3–4位合法身分就座，僅房主開局；單機由本人配置AI席位與難度。
2. 建立14張唯一牌，選2張私密藥方，其餘平均發牌。3人每人4張、4人每人3張。
3. 寶盒封牌演出先完成，發牌逐張到實際玩家格子；手機縮放後終點仍正確。
4. waiting → playing → 問牌待回應 → 交牌演出 → postQuestion → 下一合法玩家。
5. playing → followGuessing → 結果確認；若仍有資格者，回 playing，否則 roundEnd。
6. roundEnd 全員有效確認後才進下局；達本版本門檻則 finished。
7. 任一流程只能由有效事件推進一次；重送不能重複扣牌、加分或開局。

「問牌待回應／交牌演出」是目標產品階段，不表示多人後端已有對應狀態。#14仍缺確認前不變更手牌的權威流程。

## 6. 問牌規格

- 點兩色組合即進選人／問法，不額外加無意義問牌入口。
- 目標可包含猜錯者，但不能是自己；離房與斷線政策分開處理。
- 各一張：兩色各至多1張；缺一色只交另一色1張，都無則0張。
- 其中一色全部：由被問者在有牌顏色中選一種；兩色都有時不能由問者或程式替人類選。只有一色時必須交該色全部。
- 給一張要全部：問者先付選定色1張，收另一色全部；對方沒有所求色時，不退回付出的牌。
- 不得以「有多少給多少」誤解各一張。所有移轉保留牌ID，不複製、不遺失。
- 人類回應前展示誰向誰問、兩色、問法、應交張數及必要選色；確認前不可先扣牌。
- 確認 → 牌飛入實際收牌席位 → 最後一張抵達 → 提交手牌／張數 → 開放後續操作。
- 若採自動回應，仍需可辨認停留與完整交牌演出；不能把事後通知稱為事前確認。
- 未參與者不取得轉移卡的私有ID／顏色；可見公開資訊範圍需和紀錄遮罩一起驗收。

## 7. 猜牌、跟猜與資格變更

- 寶盒展開舞台，選兩色（現行模式可重複），確認前可取消；確認後答案鎖定。
- 參與順序及輪到誰必須清楚顯示；既已失去資格者不得再次跟猜。
- 尚未輪到本人時不可送決策；結果前不能透過畫面、網路或紀錄提前看藥方。
- 猜錯後手牌原封保留，後續被問牌時才按實際行動變更；不能整手消失或變公開。
- 座位保留名字、分數、手牌張數及「停止主動行動」；本人仍收到必要交牌回應介面。
- 只剩最後一人時明示「僅剩你可猜牌，請立即猜測藥方」，禁用問牌；不允許留在可問牌狀態。
- 猜錯結果確認是結束該次結果視窗，不等於退出房間；不應誤觸返回大廳。

## 8. 結算、續局與勝利

- 先呈現牌桌結果焦點，再顯示自己的分數變化與目前分數；完整明細可展開。
- 分數變化與實際扣分不同時必須清楚（例如0分下限）；單機與多人不一致尚待修正。
- 顯示每人的結果確認進度；未全員確認時說明在等誰，不能留下無說明的「結算中」。目前此UX仍待補驗。
- 全員有效確認僅進下一局一次；新局重建牌、主動資格及回合標記，保留分數與座位。
- 整場結束顯示最終排序，明示再開局／離房；完整7分賽程與同分處置尚未驗收。

## 9. 多人、公平性與恢復

- 伺服器為多人權威，拒絕代他人操作、非回合動作、重複決策及未授權查看答案。
- 每個身分只能讀自己的私牌，重連不可取得他人的手牌；猜錯者也不例外。
- 重整／重連恢復房間、本人手牌、回合、待回應狀態；斷線不能變成猜錯，不能重發同一手牌。
- 本機QA用暫存記憶體房間，不連正式房。重啟清空屬已知限制，不宣稱持久化驗收。
- Cloud Run 多實例路由、共享房間及服務重啟復原未驗，不能以單實例Socket握手當可靠多人保證。

## 10. 發布門檻與未完成工作

P0：私牌／答案外洩、越權、牌數不守恆、重複扣分或無法繼續。
P1：#14確認前扣牌；單機／多人猜錯計分差異；空手錯誤失去資格；規則差異未界定即宣稱原版。
P2：對比、狀態文字及確認進度等可用性問題，阻礙手機主要操作時升P1。

發布前須：P0/P1關閉或有明確的核准例外；所有核心案例在最新版本本機多人重驗；必須註明身分數、模式、尺寸、事件證據及未測範圍。舊QA只可作歷史證據。
測試、審查、分支合併與部署是獨立步驟；本文件完成不代表授權繞過既有發布防線。
